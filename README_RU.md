# SingRoute

[English](README.md) | [Русский](README_RU.md)

Безопасное portable-приложение для Windows, которое синхронизирует proxy
outbound из экспортов HAPP или NekoBox с конфигурацией sing-box на роутере
OpenWrt.

> SingRoute — независимый неофициальный проект. Он не связан с SagerNet или
> проектом sing-box, не спонсируется и не одобряется ими. Название sing-box
> используется только для описания совместимости.

## Возможности

1. Подключается к OpenWrt по SSH и сохраняет сессию для следующих действий.
2. Импортирует JSON из буфера обмена или файла конфигурации HAPP/NekoBox.
   Ctrl+V принимает текст конфига и один скопированный файл; неподходящий формат
   отклоняется до загрузки. В полях подключения Ctrl+V для обычного текста
   работает как стандартная вставка. Один локальный файл также можно перетащить
   в любое место главного окна.
3. Преобразует поддерживаемый proxy outbound в формат sing-box.
4. Показывает текущий и новый outbound, скрывая пароли, UUID и приватные ключи.
5. Проверяет временную конфигурацию командой `sing-box check`.
6. После успешной проверки создаёт временную резервную копию на роутере.
7. Атомарно устанавливает конфигурацию и перезапускает службу OpenWrt.
8. Проверяет службу и автоматически откатывает изменения при ошибке.
9. Загружает проверенные обновления SingRoute, заменяет portable EXE после
   закрытия и запускает обновлённое приложение.

SingRoute поддерживает нативные outbounds sing-box, HAPP/Xray VLESS Reality TCP
и HAPP Hysteria2.

## Portable-режим

Скачайте и запустите единственный файл:

```text
SingRoute.exe
```

Повторный запуск из той же папки открывает уже работающее окно и разворачивает
его, если оно свёрнуто.

Версия 0.5.0 добавляет перенос файла в окно, вставку скопированного файла через
Ctrl+V и пояснение о неподдерживаемом транспорте VLESS при импорте. Перед заменой
она также проверяет наличие корректного активного outbound на роутере.

Python и установщик не требуются. После сохранения настроек рядом с EXE
создаётся файл:

```text
SingRoute.ini
```

При переходе с `v0.1.0` SingRoute автоматически прочитает старый файл
`singbox-outbound-updater.ini` и перенесёт сохранённые учётные данные Windows
при первом использовании. Текст импортированной конфигурации не сохраняется,
поскольку может содержать секреты.

## Обновление SingRoute

По умолчанию SingRoute проверяет официальный последний релиз на GitHub при
запуске. Автопроверку можно отключить в дополнительных настройках, а ручная
проверка всегда доступна кнопкой в верхней части окна. После явного согласия
пользователя portable-версия загружает точный официальный EXE. Установка
начинается, только если его SHA-256 совпадает с digest, опубликованным GitHub.

Проверенный файл сохраняется рядом с `SingRoute.exe`. Затем отдельный системный
процесс закрывает SingRoute, ждёт освобождения EXE всеми процессами PyInstaller,
заменяет файл с возможностью отката и снова запускает программу. Версия 0.3.3
добавляет этот полный сценарий автоматической замены и перезапуска.
Версия 0.3.5 исправляет запуск helper из frozen-приложения и требует от него
сигнал готовности до закрытия SingRoute, исключая тихий срыв обновления.
Версия 0.4.0 сохраняет предыдущий EXE, пока GUI обновлённой версии не сообщит о
готовности и не пройдёт проверку стабильности. При ошибке новая версия
останавливается, выполняется откат и проверяется повторный запуск восстановленной
версии. Она также запускает оба EXE в независимом окружении PyInstaller, чтобы
они не использовали уже удалённую временную распаковку старого процесса. Файл
`.sha256` намеренно больше не публикуется: SingRoute 0.3.5 и старее не должны
переходить к своему небезопасному сценарию автоматической замены.

Версия 0.4.0 улучшает диагностику установщика, сообщает об оставшихся файлах
отката, которые помешают следующему автоматическому обновлению, и различает в
интерфейсе обновление приложения и изменение конфига роутера.

**Первый переход с SingRoute 0.3.5 или старее на 0.4.0 нужно выполнить вручную:**
закройте все процессы SingRoute, скачайте официальный `SingRoute.exe` и замените
им прежний файл с тем же именем. Не оставляйте новую версию рядом под другим
именем. Логику установки всегда выполняет уже запущенная старая версия, поэтому
только последующие обновления из 0.4.0 будут защищены новым health-check и
откатом.

Настройки подключения по умолчанию:

- роутер: `192.168.1.1`;
- SSH-пользователь: `root`;
- SSH-порт: `22`;
- конфигурация: `/etc/sing-box/config.json`;
- служба: `/etc/init.d/sing-box`.

Основная строка подключения содержит адрес, пользователя, пароль и флажок его
сохранения. Кнопка-глаз в поле пароля временно показывает или снова скрывает
введённый пароль. SSH-порт, способ авторизации, приватный ключ, путь к
конфигурации и имя службы находятся в дополнительных настройках.

## SSH и безопасность

Автоматический режим последовательно использует SSH-agent, стандартные ключи
из `%USERPROFILE%\.ssh`, `IdentityFile` из SSH config и введённый пароль.
Нестандартный приватный ключ можно выбрать вручную; приложение его не копирует.
Это приватный ключ пользователя для авторизации: он остаётся в Windows и не
является host key роутера, описанным ниже.

Пароли и passphrase ключей никогда не записываются в INI. Если сохранение
пароля включено, он хранится в Windows Credential Manager и привязывается к
пользователю, адресу и порту роутера.

Неизвестный SSH host key роутера требует явного подтверждения fingerprint.
Подтверждённый публичный ключ сохраняется в INI и служит для приложения
единственным источником доверия к этому роутеру; последующее изменение ключа
блокирует подключение.

Версия 0.3.1 также использует приватный каталог со случайным именем на роутере,
атомарную блокировку обновления до окончания проверки службы или отката и
проверку хеша непосредственно перед установкой. При замене сохраняются владелец
и режим доступа исходного конфига. Статус службы проверяется сразу и повторно
после задержки стабильности, и только затем удаляется резервная копия. При
неоднозначном обрыве SSH программа сверяет фактическое состояние до перезапуска
или отката, ограничивает размер входной конфигурации и SSH I/O восемью МиБ,
скрывает больше видов секретных полей и удаляет устаревшие учётные данные Windows
при смене адреса подключения. Установку конфигурации нельзя прервать посередине,
чтобы сохранить возможность автоматического отката.

## Разработка

Для разработки требуются Python 3.11–3.14 и Poetry.

```powershell
poetry config virtualenvs.in-project true --local
poetry install
poetry run ruff check .
poetry run ruff format --check .
poetry run pytest -q --cov=singroute --cov-report=term-missing
poetry run pip-audit
poetry run python main.py
```

## Сборка

```powershell
.\build.ps1
```

Готовый portable-файл создаётся здесь:

```text
dist\SingRoute.exe
```

Проверка упакованного EXE и полного цикла замены/отката:

```powershell
.\scripts\e2e_test_portable_update.ps1 dist\SingRoute.exe
```

E2E-тест собирает временную frozen-версию старого приложения, пропускает
production EXE через настоящий код загрузки и подготовки, устанавливает его
настоящим Windows helper и проверяет, что новый GUI запускается и продолжает
работать. Перед этим тест извлекает `update.ps1` из production-архива PyInstaller
и побайтно сравнивает с исходным ресурсом. Затем тест устанавливает заведомо
неподходящий EXE и проверяет, что прежняя frozen-версия восстановлена и запущена.
Все тестовые файлы и процессы находятся в уникальном временном каталоге.

## Выпуск версии

Версия задаётся в `pyproject.toml`. Для публикации GitHub Release создайте и
отправьте тег с той же версией:

```powershell
git tag -a v0.5.0 -m "Release v0.5.0"
git push origin v0.5.0
```

Workflow `Release` проверит метаданные и форматирование, зависимости Python и
тесты на Windows с branch coverage не ниже 70%, соберёт `SingRoute.exe`, прогонит
обе проверки упакованного приложения, создаст аттестацию сборки и опубликует EXE
в GitHub Releases. Если тег не совпадает с версией проекта, публикация не
начнётся. Актуальные версии напрямую проверяют SHA-256 digest от GitHub;
отдельный legacy-checksum намеренно отсутствует, чтобы первый переход с
SingRoute 0.3.5 и старее выполнялся вручную.

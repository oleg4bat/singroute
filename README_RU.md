# SingRoute

[English](README.md) | [Русский](README_RU.md)

Безопасное portable-приложение для Windows, которое синхронизирует proxy
outbound из экспортов HAPP или NekoBox с конфигурацией sing-box на роутере
OpenWrt.

> SingRoute — независимый неофициальный проект. Он не связан с SagerNet или
> проектом sing-box, не спонсируется и не одобряется ими. Название sing-box
> используется только для описания совместимости.

## Возможности

1. Подключается к OpenWrt по SSH и сохраняет сессию для следующих действий.
2. Импортирует JSON из буфера обмена или файла конфигурации HAPP/NekoBox.
3. Преобразует поддерживаемый proxy outbound в формат sing-box.
4. Показывает текущий и новый outbound, скрывая пароли, UUID и приватные ключи.
5. Проверяет временную конфигурацию командой `sing-box check`.
6. После успешной проверки создаёт временную резервную копию на роутере.
7. Атомарно устанавливает конфигурацию и перезапускает службу OpenWrt.
8. Проверяет службу и автоматически откатывает изменения при ошибке.
9. Загружает проверенные обновления SingRoute, заменяет portable EXE после
   закрытия и запускает обновлённое приложение.

SingRoute поддерживает нативные outbounds sing-box, HAPP/Xray VLESS Reality TCP
и HAPP Hysteria2.

## Portable-режим

Скачайте и запустите единственный файл:

```text
SingRoute.exe
```

Python и установщик не требуются. После сохранения настроек рядом с EXE
создаётся файл:

```text
SingRoute.ini
```

При переходе с `v0.1.0` SingRoute автоматически прочитает старый файл
`singbox-outbound-updater.ini` и перенесёт сохранённые учётные данные Windows
при первом использовании. Текст импортированной конфигурации не сохраняется,
поскольку может содержать секреты.

## Обновление SingRoute

По умолчанию SingRoute проверяет официальный последний релиз на GitHub при
запуске. Автопроверку можно отключить в дополнительных настройках, а ручная
проверка всегда доступна кнопкой в верхней части окна. После явного согласия
пользователя portable-версия загружает только точные официальные файлы EXE и
checksum. Установка начинается, только если checksum, digest файла в GitHub и
хеш загруженного файла совпадают.

Проверенный файл сохраняется рядом с `SingRoute.exe`. Затем отдельный системный
процесс закрывает SingRoute, ждёт освобождения EXE всеми процессами PyInstaller,
заменяет файл с возможностью отката и снова запускает программу. Версия 0.3.3
добавляет этот полный сценарий автоматической замены и перезапуска.
Версия 0.3.5 исправляет запуск helper из frozen-приложения и требует от него
сигнал готовности до закрытия SingRoute, исключая тихий срыв обновления.

Настройки подключения по умолчанию:

- роутер: `192.168.1.1`;
- SSH-пользователь: `root`;
- SSH-порт: `22`;
- конфигурация: `/etc/sing-box/config.json`;
- служба: `/etc/init.d/sing-box`.

Основная строка подключения содержит адрес, пользователя, пароль и флажок его
сохранения. Кнопка-глаз в поле пароля временно показывает или снова скрывает
введённый пароль. SSH-порт, способ авторизации, приватный ключ, путь к
конфигурации и имя службы находятся в дополнительных настройках.

## SSH и безопасность

Автоматический режим последовательно использует SSH-agent, стандартные ключи
из `%USERPROFILE%\.ssh`, `IdentityFile` из SSH config и введённый пароль.
Нестандартный приватный ключ можно выбрать вручную; приложение его не копирует.
Это приватный ключ пользователя для авторизации: он остаётся в Windows и не
является host key роутера, описанным ниже.

Пароли и passphrase ключей никогда не записываются в INI. Если сохранение
пароля включено, он хранится в Windows Credential Manager и привязывается к
пользователю, адресу и порту роутера.

Неизвестный SSH host key роутера требует явного подтверждения fingerprint.
Подтверждённый публичный ключ сохраняется в INI и служит для приложения
единственным источником доверия к этому роутеру; последующее изменение ключа
блокирует подключение.

Версия 0.3.1 также использует приватный каталог со случайным именем на роутере,
атомарную блокировку обновления и проверку хеша непосредственно перед
установкой. При неоднозначном обрыве SSH программа сверяет фактическое состояние
до перезапуска или отката, ограничивает размер входной конфигурации и SSH I/O
восемью МиБ, скрывает больше видов секретных полей и удаляет устаревшие учётные
данные Windows при смене адреса подключения. Установку конфигурации нельзя
прервать посередине, чтобы сохранить возможность автоматического отката.

## Разработка

Для разработки требуются Python 3.11–3.14 и Poetry.

```powershell
poetry config virtualenvs.in-project true --local
poetry install
poetry run pytest
poetry run pip-audit
poetry run python main.py
```

## Сборка

```powershell
.\build.ps1
```

Готовый portable-файл создаётся здесь:

```text
dist\SingRoute.exe
```

## Выпуск версии

Версия задаётся в `pyproject.toml`. Для публикации GitHub Release создайте и
отправьте тег с той же версией:

```powershell
git tag -a v0.3.5 -m "Release v0.3.5"
git push origin v0.3.5
```

Workflow `Release` проверит метаданные и зависимости Python, запустит тесты на
Windows, соберёт `SingRoute.exe`, создаст SHA-256 и аттестацию сборки, после чего
опубликует файлы в GitHub Releases. Если тег не совпадает с версией проекта,
публикация не начнётся.
